# 工业界的大模型数据：来源、生产流程与可借鉴的做法

这篇文档说明工业界训练和评测大模型时，数据实际从哪来、经过哪些处理、以什么形式进入训练和决策。重点不是罗列数据集，而是讲清楚每个环节在解决什么问题，以及哪些做法可以搬到学术研究里。

学术工作和工业界在数据上的差别，主要不是规模，而是数据在生产流程中的位置。学术工作通常从一个固定的、公开的、为比较而设计的数据集出发；工业界的数据是产品和基础设施运行时的副产物，规模大、私有、分布随产品变化，并且必须同时满足法务、隐私、成本和上线指标。理解这一点，才能理解下面那些看起来“多余”的环节为什么存在。

## 预训练数据

### 网页

网页是绝大多数大模型预训练语料的主体。工业界的做法可以分成两类：使用现成的 Common Crawl，或者自建爬虫。

Common Crawl 是一个非营利项目，每月抓取一次公开网页，单次覆盖数十亿页面，原始 WARC 文件在 PB 量级，任何人都能下载。它的问题是噪声极大：导航栏、广告、模板文本、机器翻译垃圾、重复镜像都混在一起，直接拿来训练效果很差。因此它通常只是原料，后面必须接一整套清洗。

自建爬虫的动机有三个。第一，Common Crawl 的覆盖和新鲜度不一定匹配产品需求，比如需要特定语言、特定垂直站点或更新的内容。第二，可以控制抓取礼仪和合规边界，例如遵守 `robots.txt`、限制频率、排除已知的付费墙和侵权站点。第三，可以在抓取阶段就带上来源、时间、许可证等元信息，方便后续审计。代价是工程量大、法律风险要自己承担，所以通常只有头部实验室和云厂商会做。

无论哪种来源，工业界普遍会做“域名级”的质量判断：哪些站点整体可信、哪些站点是内容农场、哪些站点需要整站排除。这种判断往往来自人工维护的名单加上模型打分，而不是逐页判断。

### 授权与专有语料

公开网页之外，工业界会花钱买数据。常见类别包括新闻通讯社的存档、图书全文、学术期刊、论坛和问答社区的历史内容、金融与法律文本、医疗记录（在合规前提下）。这类数据通常以商业授权或 API 合作的形式获得，合同里会写清使用范围、能否用于训练、能否转授权、以及模型输出是否可能复现原文。

这类合作在 2023 年之后明显增多，直接原因是版权诉讼。纽约时报诉 OpenAI、作者协会诉 OpenAI、Getty Images 诉 Stability AI 等案件让“训练数据是否构成合理使用”变成真实的商业风险，于是“先拿授权再训练”从可选项变成了部分场景的必选项。对应的工程变化是：数据团队需要记录每条数据的来源和许可证，模型发布前要能做数据血缘追溯。这不是学术数据集常见的字段，但在工业界是硬要求。

### 代码、书籍与学术文本

代码数据有自己的特殊性。工业界通常只使用宽松许可证（MIT、Apache-2.0、BSD 等）的代码，或者提供 opt-out 机制让作者排除自己的仓库。GitHub 上的代码量大，但许可证混杂，直接抓取会带来合规问题。StarCoder 系列公开过一套“按许可证过滤 + 尊重 opt-out”的流程，可以作为参考。

书籍和学术文本的价值在于长程连贯性和领域深度，但获取成本高、版权风险大。公开的 Books3 数据集在 2023 年因 DMCA 投诉被下架，The Pile 也随之移除了这一部分。工业界的替代方案通常是授权采购，或者用合成数据部分模拟这类文本的结构。

### 合成数据

合成数据在预训练和后训练里都用得越来越多。预训练阶段的典型做法是让强模型改写、翻译、扩写或生成教科书风格的文本，再混入真实语料。phi 系列是公开案例：它用“教科书质量”的合成文本训练小模型，验证了数据质量和结构可以在一定程度上替代数据规模。

合成数据的风险也很明确。第一，分布会向生成模型自身的偏好收缩，长期只用合成数据会导致多样性下降，相关研究把它称为 model collapse。第二，如果合成数据来自某个闭源模型的输出，可能违反该模型的服务条款。第三，合成数据的“正确性”没有自动保证，尤其在事实和数学推理上，需要额外的验证环节。工业界的常见做法是：合成数据只占配比的一部分，并且尽量配合可验证的筛选（单元测试、答案匹配、人工抽检）。

### 公开的工业级数据集

工业界内部数据通常不公开，但出于生态、合规或研究目的，会发布经过处理的版本。这些数据集是学术研究者了解工业数据形态的最直接材料：

- C4（T5 论文）展示了“从 Common Crawl 用启发式规则筛出 156B tokens”的基线流程，很多后续工作把它当作对照。
- The Pile 把 22 个来源（网页、书籍、代码、学术、对话等）按权重混合成 825 GiB，是“多源配比”的公开模板。
- RefinedWeb 证明只靠 Common Crawl 加严格过滤也能得到 5T tokens 级别的语料，公开版本约 600B tokens。
- RedPajama、Dolma、FineWeb、DCLM 是近两年公开的开放语料，规模从 1T 到 15T tokens 不等，并且附带较完整的清洗说明和消融实验。它们让“工业级清洗”从黑箱变成可复现的流程。

这些数据集的共同价值不在于“拿来就能训出一个好模型”，而在于它们公开了数据决策：用什么过滤器、去重到什么程度、各来源占多少比例、这些选择对下游指标有什么影响。

## 从原始数据到训练集：清洗流水线

一条典型的预训练数据流水线包含下面这些环节。顺序不是固定的，不同团队会调整，但每个环节要解决的问题是共通的。

**文本抽取与语言识别。** 从 HTML 里去掉导航、广告、脚本，保留正文。工具包括 trafilatura、resiliparse 等。然后用 fastText 之类的轻量分类器识别语言，按目标语言筛选。这一步决定了语料的语言分布，也影响后续所有过滤器的适用性。

**质量过滤。** 分两类。启发式规则看长度、标点比例、重复行比例、停用词比例、是否包含大量数字或特殊符号。模型方法用一个分类器给文本打分，常见做法是拿 Wikipedia 或人工标注的高质量文本作正例、随机网页作负例训练 fastText，或者用更强的模型做蒸馏。工业界通常两者叠加：先用便宜规则砍掉明显垃圾，再用模型在剩余数据上排序。

**去重。** 去重对训练效率和效果都有显著影响。重复文本会让模型记住而不是泛化，也会放大版权和隐私风险。常用方法从精确哈希到 MinHash LSH、后缀数组，粒度从文档级到段落级、句子级。公开研究（如 Lee et al. 2021 对 C4 的去重分析）显示，去重后困惑度和下游指标都会改善。工业界还会做“跨数据集去重”，特别是把评测集从训练集里剔掉。

**隐私与安全过滤。** 识别并移除邮箱、电话、身份证号、地址等 PII；过滤仇恨、色情、暴力和违法内容。工具包括 Presidio 之类的规则系统，以及分类器。工业界还会保留一份“不要训练”的排除名单，覆盖已知的敏感站点和用户请求删除的内容。

**许可证与合规过滤。** 对代码和部分文本，按许可证白名单筛选；记录来源和时间；对 opt-out 请求建立可执行的删除流程。这一步在学术数据集里很少见，但在工业界是上线前的必经环节。

**去污染。** 把评测集的题目、答案和近似变体从训练语料里剔除。常用方法是 n-gram 重叠检测、MinHash、以及针对 benchmark 的 canary string。GPT-4 的技术报告公开过一套污染检测流程，包括把训练数据切片后搜索 benchmark 原文。这件事在工业界是常规操作，因为 benchmark 分数直接用于对外宣传和内部决策。

**配比与课程。** 不同来源的数据按权重混合。权重可以靠经验设定，也可以用 DoReMi 这类方法在小模型上搜索域权重再迁移到大模型。课程学习则是分阶段调整数据分布，比如先通用网页、后高质量领域数据。配比是工业界最“玄学”也最敏感的部分，因为它直接影响模型的能力分布，而且很难从小规模实验完全预测。

**规模与重复。** 在数据受限的情况下，工业界会重复使用语料。相关研究表明，重复到一定次数后收益递减，且重复高质量数据比重复低质量数据更有效。这解释了为什么“清洗 + 去重 + 配比”往往比“多抓一点网页”更划算。

## 后训练数据

后训练数据决定模型“怎么说话、听不听话、会不会拒绝”。它比预训练数据规模小得多，但对标注质量和流程设计的要求更高。

### SFT 数据

监督微调的数据通常由人工撰写、人工筛选或模型生成后人工审核。内容包括多轮对话、工具调用、长文档问答、代码修复、拒绝不当请求等。工业界的共识是质量优先于数量：LIMA 用 1,000 条精心挑选的示例就得到了有竞争力的对话模型，说明 SFT 阶段的数据多样性和质量比规模更关键。

专家数据是另一个方向。医疗、法律、金融、科研等场景需要领域专家撰写或审核，成本高，但能显著改善专业任务的表现。工业界通常按“领域 × 任务类型 × 难度”设计数据矩阵，而不是随机采样。

合成 SFT 数据的代表是 Self-Instruct：用少量种子指令让强模型生成大量指令和回答，再筛选。Evol-Instruct 进一步用“演化”操作增加指令的复杂度和多样性。工业界的合成流程通常比论文更保守：生成后要过去重、去污染、正确性检查和人工抽检。

### 偏好数据

偏好数据用于训练奖励模型或直接做偏好优化（RLHF、DPO 等）。基本形式是同一个 prompt 下的两个回答，标注员判断哪个更好，或者给出细粒度评分。

InstructGPT 公开的流程是：约 40 名标注员，用约 13k 条 prompt 写了演示数据做 SFT，收集约 33k 条 pair 比较训练奖励模型，PPO 阶段又用了约 31k 条 prompt。Anthropic 的 HH-RLHF 公开了约 16 万条比较。UltraFeedback 用多个模型生成回答再做比较，规模约 64k prompts。这些数字说明，偏好数据的规模通常在十万量级，远小于预训练，但每条数据的标注成本高得多。

工业界在偏好数据上的关键工程是标注指南和一致性控制：把“有用、无害、诚实”拆成可操作的标准，做试点批校准，用 gold question 检查标注员，计算标注者间一致性（如 Cohen's kappa、Krippendorff's alpha），对分歧样本做裁决。这些做法在学术论文里通常只写一句“人工标注”，但它们是工业界数据质量的主要来源。

### 可验证奖励

数学和代码任务可以用程序验证答案，因此能低成本生成大量高质量奖励信号。数学题用答案匹配或符号验证，代码用单元测试执行。这类数据让强化学习不必依赖人类偏好，绕开了奖励模型的偏差和标注成本。

过程监督是进一步的细化：不只判断最终答案对错，还对推理的每一步打标签。OpenAI 的 PRM800K 公开了约 80 万条步骤级标签，用于训练过程奖励模型。工业界在数学、代码、形式化证明等可验证领域大量使用这类数据，因为它们能直接提升推理能力，而且信号干净。

### 评分标准与 LLM judge 数据

当任务难以用程序验证时，工业界会用评分标准（rubric）让人或模型打分。rubric 把“好回答”拆成若干维度，每个维度有明确的等级描述。这类数据用于训练奖励模型、校准 LLM judge、以及做离线评测。

LLM-as-judge 的工业用法通常包含三步：先用人类标注校准 judge 与人的一致性，再在大规模候选中用 judge 排序，最后对 judge 的偏差做修正（位置偏差、长度偏差、风格偏好）。公开研究如 MT-Bench 和 Chatbot Arena 提供了 judge 与人类偏好一致性的基准，但工业界更关心的是在自己的任务分布上的一致性，因此会维护私有校准集。

### 安全数据

安全数据包括红队对抗样本、拒答示例、边界案例、以及针对特定风险的分类体系。工业界的做法通常是把安全要求和产品政策拆成类别，每类收集正反例，再混入 SFT 和偏好数据。红队可以是内部团队、外部专家或自动化生成，目标是覆盖已知攻击面和长尾风险。

## 评测数据

评测数据在工业界不是“论文里的表格”，而是产品决策的一部分。它要回答的问题包括：模型是否比上一版好、好多少、在哪些场景变差、上线后用户是否满意、是否触发了安全或合规风险。

### 公开 benchmark 与污染

MMLU、GSM8K、HumanEval、BBH、GPQA 等公开 benchmark 是行业共同的参照系，但它们面临两个问题。第一，饱和：头部模型在多数基准上已经接近上限，区分度下降。第二，污染：训练语料里混入了题目或近似变体，分数虚高。

工业界的应对包括：在训练数据里做去污染；保留不公开的 held-out 集；使用动态更新的 benchmark（如 LiveBench 定期换题）；以及在报告分数时同时说明污染检测结果。BIG-bench 的 canary string 是一种公开约定：在 benchmark 文件里嵌入特殊字符串，训练方如果发现语料里有这个字符串，就知道数据被污染了。

### 内部评测集

内部评测集是工业界真正的“主考场”。它通常由产品场景的真实请求构成，按任务类型、难度、语言、用户群切片，并且持续更新。特点是私有、贴近分布、迭代快。内部评测集的质量取决于采样和标注：如果只采样容易的例子，模型会看起来很好但上线翻车；如果标注标准不统一，分数波动会掩盖真实差异。

工业界通常维护多套评测：能力评测（知识、推理、代码）、行为评测（指令遵循、格式、工具调用）、安全评测（拒答、越狱、偏见）、以及回归评测（防止新版本破坏旧能力）。回归集是工程化的关键，它让“改一个 prompt 或换一版数据”的副作用可见。

### 在线评测

离线分数和真实用户体验之间的差距，是工业界最常讨论的问题之一。在线评测的主要形式是 A/B 测试：把用户随机分到不同模型版本，比较留存、参与度、任务完成率、点赞/点踩、投诉率等指标。优点是直接反映真实分布，缺点是需要流量、周期长、且只能比较少量版本。

在线评测还会加入人工抽检和用户反馈回路：对线上对话采样，由标注员按 rubric 打分；把用户点踩的样本回流到训练和评测集。这个“数据飞轮”是工业界数据优势的核心：产品使用产生日志，日志经过筛选变成训练和评测数据，模型改进后又产生新的日志。

### 人评与 LLM-as-judge

人评是金标准，但成本高、速度慢、一致性难保证。工业界通常用“少量人评校准 + 大规模 judge 排序”的组合。judge 的选择和提示词会影响结果，因此需要固定版本、固定提示、并定期用人类样本复核。Chatbot Arena 的众包 pairwise 投票是另一种思路：用大量用户的偏好代替专家标注，覆盖真实分布，但难以控制标注质量和对抗性刷票。

### 评测的工程化

工业界的评测系统通常具备这些特征：评测集版本化、评测脚本可复现、结果按切片报告、置信区间和显著性检验、以及评测与训练数据的隔离。学术论文常报单一分数，工业界更关心“在哪些切片上变差”和“差异是否显著”。这不是形式主义，而是因为上线决策需要知道风险边界。

## 组织与运营

数据工作在大模型公司里通常是一个独立职能，包含数据策略、数据工程、标注运营、法务合规、以及和安全团队的交界。几个值得了解的点：

**标注供应商与专家网络。** 通用标注通常外包给 Scale AI、Surge AI、Invisible 等供应商，专业领域则通过专家网络招募医生、律师、工程师。供应商管理的核心是质量而非价格：试点批、gold question、盲评、以及按一致性付费，都是常见手段。

**标注流程。** 一份可用的标注指南通常要经过多轮迭代：先写初版，做小批试点，看分歧在哪里，再补充边界案例，最后才大规模生产。标注员之间的一致性用 kappa 或 alpha 衡量，分歧样本由高级标注员或领域专家裁决。这套流程决定了偏好数据和 SFT 数据的可用性。

**数据版本、血缘与文档。** 工业界会给数据集打版本，记录每个版本的来源、过滤器、配比和已知问题。数据集卡（datasheet）是常见的文档形式，内容包括动机、构成、采集方式、预处理、用途、限制和伦理考量。这让数据可以审计、可以回滚、可以在团队间交接。

**法务与隐私。** 训练数据的合法性取决于司法辖区、数据来源和使用方式。工业界通常的做法是：建立来源白名单和黑名单、记录许可证、提供 opt-out 渠道、对 PII 做脱敏、并在模型发布前做 memorization 检测（检查模型是否会逐字复现训练数据中的敏感内容）。这些工作很少出现在论文里，但直接决定数据能不能用。

## 可以直接借鉴的做法

下面这些做法不依赖工业界的规模，学术研究可以直接采用。

**把数据当实验对象。** 工业界做数据决策时会跑消融：固定模型和训练步数，只改一个数据变量（过滤器、去重强度、配比），看下游指标。FineWeb、DCLM、DataComp-LM 都公开了这类实验设计。学术工作如果只报告“用了某数据集”，很难说明数据本身的作用；把数据管线当成方法的一部分，结论会更可靠。

**小规模 proxy 加 scaling。** 直接在目标规模上做数据实验成本太高，工业界的做法是在小模型、小 token 预算上筛方案，再把胜出的方案放大。DoReMi 用 280M 参数的 proxy 模型搜索域权重，就是一个可复制的例子。需要注意的是，proxy 上的最优配比不一定在大模型上最优，因此结论要谨慎表述。

**去重与质量过滤的收益是有限但稳定的。** 去重、质量分类器、语言过滤这些“脏活”往往能带来稳定的 perplexity 和下游提升，而且实现成本低。学术工作如果要用网络语料，至少应该报告去重和过滤策略，否则结果难以比较。

**合成数据的正确用法是“补充”而不是“替代”。** phi 系列证明了高质量合成数据可以提升小模型，但它的前提是合成数据经过严格筛选，并且与真实数据混合。把合成数据当成无限量供给，通常会遇到多样性下降和事实错误累积的问题。

**偏好数据的质量取决于指南和一致性。** 如果要做 RLHF 或 DPO 相关研究，值得投入精力设计标注指南、做试点校准、报告标注者一致性。只报告“收集了 N 条偏好数据”不足以说明数据质量，也无法解释方法差异。

**可验证奖励是低成本高信号的来源。** 数学和代码任务可以用程序验证，适合做强化学习实验。过程监督（PRM）进一步提高了信号密度，但标注成本也更高。学术工作可以从可验证任务入手，避免一开始就依赖昂贵的人类偏好标注。

**污染控制应该成为默认动作。** 使用公开 benchmark 时，至少要做 n-gram 重叠检测，并报告检测结果。如果训练数据来自网络，污染几乎必然存在；不检测就等于把污染当成能力。

**评测要报告切片和方差。** 单一平均分容易掩盖差异。工业界的做法是按任务类型、难度、语言、长度等维度切片，并报告置信区间。学术工作如果要做有说服力的比较，也应该给出多 seed 的方差和切片结果。

## 值得读的公开材料

按主题分组，每条说明它能提供什么。

预训练语料与清洗：
- C4 / T5 论文：启发式过滤的基线流程。
- The Pile：多源配比和公开数据集的早期模板。
- RefinedWeb：Common Crawl 加严格过滤的规模化案例。
- RedPajama、Dolma、FineWeb、DCLM：开放语料和配套消融，适合复现清洗流程。
- DataComp-LM：把数据策展变成可比较的 benchmark。

数据配比与重复：
- DoReMi：用 proxy 模型搜索域权重。
- Scaling Data-Constrained Language Models：数据受限时的重复训练规律。

后训练数据：
- InstructGPT：SFT、奖励模型、PPO 的完整流程和标注规模。
- HH-RLHF：公开的偏好数据格式和标注方法。
- UltraFeedback：多模型生成加比较的规模化偏好数据。
- LIMA：少量高质量 SFT 的效果。
- Self-Instruct：合成指令数据的起点。
- PRM800K：过程监督的公开数据。

评测与污染：
- GPT-4 技术报告：污染检测和评测设计的工业实践。
- BIG-bench：canary string 和 benchmark 设计。
- HELM：多维度评测框架。
- Chatbot Arena / MT-Bench：人类偏好和 LLM judge 的一致性研究。
- LiveBench：动态更新以缓解污染。

工程与运营：
- 各公司的模型卡和数据集卡（OpenAI、Anthropic、Meta、Google、Hugging Face）。
- Hugging Face 的 `HuggingFaceFW`、`EleutherAI`、`allenai` 等组织页面，能看到公开数据集的构成和说明。
- Scale AI、Surge AI 等供应商的公开博客，能了解工业标注的流程和定价逻辑。
