调研日期：2026 年 10 月 10 日。

根据你补充的用途，我分别按这两个目标选型：科幻方向是把高中、大学物理知识融入虚构故事，制作物理课程大作业；科学讲解方向必须出现真实拍摄的实验或自然现象影像，并配有旁白和字幕，动画可以辅助。

**我的推荐是：科幻创作优先试 LTX Studio，开源方案选 Toonflow；实拍物理讲解优先试 Fliki，开源方案重点看 NarratoAI。** 如果更看重以后持续用程序批量生产，科幻方向再考虑 ViMax，科普方向再考虑 MoneyPrinterTurbo。

本次检索覆盖了自动短剧、影视生成 Agent、素材驱动的解说、自动配音字幕、Manim 科学动画等路线，并交叉核对了项目官方文档、GitHub 仓库、部分关键实现和发布记录。以下推荐依据是工作流与你需求的适配程度；没有用同一个题目付费生成各平台样片，因此不把它写成模型画质实测排名。开源项目的功能以本次检查的主分支为准。

| 你的使用方式 | 科幻视频 | 含实拍的物理讲解 |
| --- | --- | --- |
| 希望尽快制作第一条高质量作品 | LTX Studio | Fliki |
| 希望本地部署、可调整项目实现 | Toonflow | NarratoAI |
| 希望主要通过代码批量生产 | ViMax | MoneyPrinterTurbo |
| 希望一个收费平台兼顾生成和实拍剪辑 | invideo | invideo |

**一、科幻视频创作**

这类课程作品需要的能力是：保留你确定的物理设定，把故事拆成镜头，复用人物、场景和道具，单独修改不合格的片段，再完成声音与剪辑。支持这些操作的创作平台，比只提供一个文生视频输入框的工具更适合。

**LTX Studio：收费在线方案的首选。**

入口：[官网](https://ltx.studio/) · [故事板功能](https://ltx.studio/platform/ai-storyboard-generator) · [价格](https://ltx.studio/pricing)。

它能从剧本或概念生成故事板，提取并复用人物、物体、地点等 Elements，逐镜调整画面、参考图、运镜和关键帧，再在时间线上裁剪、安排转场与节奏。官方编辑器还提供文字转语音和配乐。对你的用途，最有价值的是可以先写好物理设定和剧情，再让平台完成视觉化；某一镜头表现错了，可以针对该镜头修改。

官网当前月付列表中，Standard 为 **35 美元/月**，AI Storyboards、可保存的 Elements 和高级节点自动化列在这一档。免费档适合体验界面和基础生成；不能把“有免费版”理解为完整创作功能都免费。生成和返工会消耗额度，订阅费不是一条完整作品的固定制作成本。

**使用边界：它适合承担科幻叙事与虚构镜头制作，实拍总剪辑能力尚不能据公开文档确认。** 官网首页写有从视频开始创作，但[时间线编辑器 FAQ](https://ltx.studio/studio/platform/ai-video-editor)又明确说不支持上传原始视频做传统剪辑。视频参考、视频再生成和原片直接入时间线是不同功能。因此，如果你要混入真实实验影像，建议把 LTX 的科幻片段导出，再在 Fliki、invideo 或剪映中与原始实拍合成。

**适合你在愿意付订阅费、希望把主要时间花在故事和画面打磨时使用。** 角色参考和一致性工具能改善连续性，但仍需要检查每个镜头，尤其是运动方向、物体数量、装置结构等与物理解释有关的细节。

**Toonflow：开源方案的首选。**

入口：[GitHub](https://github.com/HBAI-Ltd/Toonflow-app) · [下载安装包](https://github.com/HBAI-Ltd/Toonflow-app/releases)。本次最新发布为 **v2.0.5，2026-10-09**；当前许可证为 MIT。

它把剧本、人物、场景、道具、图片和视频放在同一张可编辑画布上，支持 AI Agent、资产复用、多参考素材生成、3D 导演台，以及外部模型 API、本地 ComfyUI 和 LLM。Windows 有客户端，也支持 Docker。对物理课程科幻作品，人物形象、实验装置或飞船结构可以先作为资产确定下来，再用于后续片段。

我进一步核对了它的内置节点：有[本地视频导入](https://github.com/HBAI-Ltd/Toonflow-app/blob/master/packages/nodes/videoNode/readme.md)、[音频生成](https://github.com/HBAI-Ltd/Toonflow-app/blob/master/packages/nodes/audioGenerationNode/readme.md)，以及供 Agent 调用的 [FFmpeg 合成工具](https://github.com/HBAI-Ltd/Toonflow-app/blob/master/packages/tools/ffmpeg/readme.md)。视频节点文档目前规定单文件不超过 **100 MB**，长实拍需要先分段或压缩。

它更接近“可交互、可修改的 AI 制作工作台”。默认创作流程包含剧本、资产、小样等阶段的人工确认；即使使用自动化，也应该预留这些检查。**我没有确认到一个与 Fliki 同等明确的开箱即用字幕工作流**，因此建议把统一字幕和精细总剪辑安排在剪映等工具里，或在实际安装后再确认所选插件是否满足要求。

软件本身免费，云端语言、图像、视频和语音服务按各自规则收费。仓库记录过一个约 **2 分钟成片、约 2 小时制作、约 130 元模型调用费**的案例，使用 Seedance 2.0 等模型；这是作者的单个案例，不能当作你的成本承诺。

**如果你希望使用中文创作环境，自己管理项目、模型和素材，并愿意做少量配置，我更推荐 Toonflow。** 对当前任务，先使用云端模型即可，无须为了使用这个软件先部署本地视频大模型。

**ViMax：面向程序化自动生产的首选。**

入口：[GitHub](https://github.com/HKUDS/ViMax) · [发布页](https://github.com/HKUDS/ViMax/releases)。MIT；最新发布 v1.2.0 为 2026-07-20，主分支 2026-09-30 仍有生成流程更新。

它提供 Idea2Video、Script2Video、Novel2Video 等工作流，将剧本、角色、分镜、参考图、视频生成和最终拼接组织起来。现有版本已经有 Web UI、交互式 Agent、文件上传、故事板预览、恢复渲染和供应商设置；也保留直接运行 Python 工作流的入口。不要按早期介绍把它理解成只有命令行的研究代码。

对你而言，**应优先使用 Script2Video，把已经检查过物理设定的剧本交给它**。它适合以后不断替换剧本、模型或参数，反复生产同类作品。部署需要 Python/uv，使用 Web UI 还需要 Node.js，并配置语言、图像和视频模型服务。

它的自动一致性检查也有额外成本：当前可为关键帧生成多个候选，再由视觉模型筛选。项目仍有关于[跨机位场景状态连续性的反馈](https://github.com/HKUDS/ViMax/issues/83)，不能把“有一致性机制”视作已经完全解决角色、物体和空间连续性。中文对白、字幕及不同视频供应商的声音表现，也应在正式长片前用短样片验证。

**如果目标是这次课程作业尽快出片，我先选前两者；如果目标是形成你自己的自动化制作流程，ViMax 更值得投入配置时间。**

另外几个真正相关的候选，分别适合这些情况：

- **[VideoClaw](https://github.com/HITsz-TMG/VideoClaw)**：MIT，提供剧本策划、角色与场景设计、分镜和视频生成，也有解说短视频模块；支持首帧、首尾帧和参考图等不同生成方式，能通过 Web UI 配置模型。适合愿意部署 Python、Node.js、FFmpeg，并希望同一套代码兼顾剧情和解说的使用者。2026 年仍有更新；界面和工作流值得尝试，但我没有足够依据认为它比 LTX 或 Toonflow 更适合你的第一条精修作品。
- **[LocalMiniDrama](https://github.com/xuanyustudio/LocalMiniDrama)**：MIT，Windows 有 exe；提供故事、角色、场景、道具、分镜、视频合成、一键补全生成和解说 SRT 导出。若你更喜欢列表式短剧流程，它是 Toonflow 的直接备选。这里的“本地”主要指软件和项目存储，调用云端模型仍会把对应请求和参考素材发给服务商。
- **[Jellyfish](https://github.com/Forget-C/Jellyfish)**：Apache-2.0，较重视人物、服装、场景、道具的共享资产和逐镜准备状态，适合多场景、资产较复杂的故事。Docker 部署涉及数据库、Redis 和对象存储，个人第一次做课程视频时，其管理能力带来的收益未必超过配置成本。
- **[火宝短剧](https://github.com/chatfire-AI/huobao-drama)**：有桌面包和从剧本到视频的完整制作流程，属于值得比较的直接替代品。当前许可证为 **CC BY-NC-SA 4.0**，包含非商业限制；个人课程项目可以考虑，但你还计划长期做自己的视频创作，不能把它当作无商业限制的通用底座。
- **[waoowaoo](https://github.com/waooAI/waoowaoo)**：当前公开版是预览状态，支持画布、参考素材、图像和视频生成；README 明确说明这个预览版没有音乐和配音控制。当前为 **Elastic License 2.0 的源码可用软件**，并非 OSI 认可的开源许可。它与你的用途相关，但当前功能覆盖和部署复杂度使我不会优先推荐它完成这次作品。
- **[Mootion](https://www.mootion.com/)**：适合希望从剧本快速得到完整故事视频的人，支持中文、语音配乐，并能把剧本、图片和视频片段打包下载，方便继续编辑。官网当前说明创作和下载需要付费。我把它作为快速生成叙事初稿的备选；针对严谨物理过程的画面控制，现有公开资料不足以让我把它排在前述首选之前。

**二、带实拍、配音和字幕的科学讲解视频**

你的硬要求使“真实素材如何进入成片”成为核心：工具必须能直接使用你拍摄或选定的影像，并让对应讲解出现在正确的时间。仅仅用 AI 生成逼真的实验画面不能满足这项要求。

**Fliki：最快制作第一条精细物理讲解视频的首选。**

入口：[官网](https://fliki.ai/) · [官方使用教程](https://fliki.ai/resources) · [价格与套餐](https://fliki.ai/pricing)。

Fliki 可以从已有讲稿生成视频，提供中文 AI 配音、字幕、素材库、图片和视频导入。推荐它的主要依据是官方教程明确说明了这些具体操作：

- 把自己的视频上传到 My Library，再放入指定场景；目前单文件上限为 **250 MB**。
- 选中某一段旁白文字，添加只在这段文字读出时出现的 B-roll 画面。
- 用 Trim Media 选择原视频中的具体片段，用时间范围控制它在场景中的出现位置。
- 修改场景时长、配音速度和停顿，设置字幕样式，并用发音映射处理术语或缩写。

这意味着你可以让“开始转动”“改变转动惯量”“角速度变化”等讲解，分别对应真实实验中的正确片段。实拍、示意图和 AI 生成的辅助镜头也可以在同一视频里编排。

**建议使用“已有讲稿 → 分场景 → 指定真实素材 → 自动配音字幕”的方式。** 自动选素材适合一般背景画面；具体实验过程应由你指定。图像、字幕和旁白可以自动生成，但决定哪个实拍片段能说明哪个物理结论，仍是你需要控制的部分。

当前价格页把 **1080p、最长 15 分钟视频**列入 Standard；API 访问列在 Premium。也就是说，做第一条作品可以通过网页操作；如果以后要程序批量调用，需按 API 套餐另行考虑。公开页本次没有返回具体订阅金额，因此这里不引用可能过期的价格。

它适合清楚、完整、声音和画面同步的物理讲解。复杂 3D 场景、专业粒子动画和严格的公式推演画面，需要先在其他工具里制作，再导入。

**NarratoAI：以现有真实视频为核心时，优先考虑的开源项目。**

入口：[GitHub](https://github.com/linyqh/NarratoAI) · [官方文档](https://p9mf6rjv3c.feishu.cn/wiki/SP8swLLZki5WRWkhuFvc2CyInDg) · [仓库推荐的整合包入口](https://cutagent.online/)。MIT；本次最新 GitHub 发布为 **v0.8.7，2026-07-17**。

它的基本流程是：分析已有视频，生成带时间范围的解说脚本，按脚本剪辑原片，再生成配音和字幕。虽然项目定位是影视解说，但已实现纪录片逐帧分析，也支持自定义脚本编辑、多个 TTS 引擎及剪映草稿导出。这些能力与你“真实影像加讲解”的要求直接相关。

我核对了[剪映草稿导出实现](https://github.com/linyqh/NarratoAI/blob/main/app/services/jianying_task.py)：它会保存原始素材时间范围、旁白音频、字幕等信息，构建可继续编辑的草稿。这比只拿到一个已压平的 MP4 更有利于调整实验步骤、解说节奏和画面标注。官方给出的建议配置为 4 核 CPU、8 GB 内存，显卡非必需；本地语音模型另有硬件需求。

**适合你已经有一段或一组实验录像，希望围绕画面写讲解并自动剪辑。** 使用时应人工改写其面向影视叙事的文案，把物理条件、观察结果和推论写清楚；视觉模型看到了一个现象，不代表它就能可靠解释原因。

它有两个与选择有关的限制。第一，README 仍把“根据口播、文案、视频素材自动匹配”列为待办，因此不能承诺任意讲稿加素材库就能完美对齐。第二，项目仍有[批量视频生产与预定义工作流的功能请求](https://github.com/linyqh/NarratoAI/issues/274)，目前不应把它当成成熟的无人值守批量生产系统。你若更重视单条作品的可编辑性，它比这一限制更有吸引力。

**MoneyPrinterTurbo：适合长期批量制作素材型科普的开源首选。**

入口：[GitHub](https://github.com/harry0703/MoneyPrinterTurbo) · [下载安装包](https://github.com/harry0703/MoneyPrinterTurbo/releases)。MIT；本次最新发布为 **v1.3.8，2026-10-03**，主分支仍在更新。

它的整条流程很完整：自定义或生成讲稿、配音、素材、字幕、背景音乐、视频合成。现有项目提供 Web UI、API、CLI 和 Agent 入口，支持批量生成、本地视频与图片、Pexels/Pixabay 等素材来源，多种中文 TTS，以及云端生成视频素材。它并不局限于早期版本的库存视频拼接。

它适合把你已整理好的讲稿和素材持续转成同一风格的视频，也是这次检索中自动化入口最齐全的科普候选之一。使用现成实拍、本地合成和 Edge TTS 时，不必付视频生成模型的费用；Edge TTS 本身仍是联网语音服务。

**但它不是我给你这条精细实验讲解视频的第一推荐。** 本次检查的[参数定义](https://github.com/harry0703/MoneyPrinterTurbo/blob/4204d0f39afa8ada6f3edc31604141f959fe254e/app/models/schema.py)中，默认素材顺序是随机、片段时长是 5 秒；[拼接实现](https://github.com/harry0703/MoneyPrinterTurbo/blob/4204d0f39afa8ada6f3edc31604141f959fe254e/app/services/video.py)在顺序模式下会取各素材的开头片段。这些默认行为适合短视频素材组织，但可能截掉实验关键过程。打开顺序匹配，也不等于已经获得逐句旁白与实验时间点的精确绑定。

如果用它完成你的需求，应先把实验录像剪成明确的演示片段，检查片段时长与播放顺序，再生成成片；不要把一段长实验录像直接投入默认流程。需要保留完整实验过程、精确字幕和图示落点时，Fliki 或 NarratoAI 加剪映更方便。

**invideo：想在一个收费平台里兼顾实拍剪辑和 AI 创作时，值得优先试。**

入口：[官网与当前编辑器](https://invideo.io/ai/) · [帮助中心](https://help.invideo.io/en/) · [配音](https://invideo.io/make/ai-voice-generator/) · [字幕](https://invideo.io/make/ai-subtitle-generator/)。

当前公开产品已包含 Agent 驱动的剪辑、原始素材上传、自然语言查找片段、批量调整镜头和可接管的多轨时间线，也提供故事板、配音与字幕。对于“实验实拍 + 科幻引入 + 原理图解”这种混合视频，它的工具范围比 Fliki 更广。它也因此是一个值得试的单平台方案。

我仍把 Fliki 放在直接制作旁白型科普的首位，因为它的逐场景、逐段旁白绑定与素材裁剪方式，在官方操作文档里更明确。若你需要更多轨道、较复杂的音效和镜头调整，则更值得试 invideo。官网当前月付列表为 Starter 20 美元、Plus 60 美元，但 Agent 能力、模型和素材额度分档，不能只比较最低价。

**Pixelle-Video：想统一科普画面模板、混合自有素材和生成素材时的备选。**

入口：[GitHub](https://github.com/ATH-MaaS/Pixelle-Video) · [使用文档](https://aidc-ai.github.io/Pixelle-Video/zh)。Apache-2.0，2026 年仍有模型 API 接入更新。

它能完成文案、配图或视频、语音、背景音乐和合成，支持固定讲稿、上传自定义素材、HTML 画面模板、Python API、ComfyUI/RunningHub 及直连模型服务。Windows 有整合包。它适合把一组科普视频制作成统一视觉风格，尤其是画面中有较多文字卡片、插图和生成素材时。

不过，自定义素材输入有分析和生成流程，不能仅凭“允许上传视频”就认定上传的实验原片会原样进入最终时间线。我未完成这部分保真链路的端到端验证，因此没有把它排在 Fliki、NarratoAI 之前；也没有确认其所有模板都提供与配音逐字同步、可单独导出的字幕。

**三、用于补充原理动画的项目**

这些项目能提高科学讲解的表现力，但不能代替你要求的实拍部分。对于坐标轴、矢量、波形、受力图和公式，程序绘制的动画更便于核对参数与关系。

**[Auto Pop-Sci](https://github.com/0x68616F4C/auto-popsci)** 最贴近“中文旁白 + 科学动画 + 字幕”的完整辅助流程。它提供叙事、讲稿、Manim 动画、Edge TTS、FFmpeg 合成和基于时间戳的 SRT 生成，默认参数包括中文和中文音色，并附有可构建的示例。它本质上是一套供编程 Agent 使用的工作流程和模板，项目规模较小，没有成熟视频编辑器的交互界面。适合在你愿意让 AI 编写并修改动画代码时，用来补上原理解释镜头。

**[Math-To-Manim](https://github.com/HarleyCoops/Math-To-Manim)** 更值得关注的是数学与物理的视觉表达。当前有从问题到知识整理、视觉规划、Manim 编写、实际渲染和检查的链路，示例包含轨道等物理题材，近期仍在更新。它更适合作为几何、公式或三维原理画面的制作工具；本次没有确认通用入口能够同时自动输出你所需的中文旁白和字幕，不能把它推荐成完整科普成片的一键替代方案。

**[TheoremExplainAgent](https://github.com/TIGER-AI-Lab/TheoremExplainAgent)** 提供较完整的长篇定理讲解视频生成、Manim 代码生成与修正、Kokoro 语音和批量处理。它更偏研究工具，README 的语音配置默认英文，最后推送时间为 2025 年 7 月，安装涉及 Manim、LaTeX 和语音模型；中文适配、Windows 环境与现有依赖都需要额外检查。它仍有参考价值，但对你现在要完成的物理视频，我不会优先于较新的中文工作流。

如果只缺“让已写好的 Manim 动画跟着旁白走”，可以直接用 **[Manim Voiceover](https://github.com/ManimCommunity/manim-voiceover)**。它能使用 TTS 或录音，并在指定单词处触发动画，是一个功能明确的组件；它本身不负责从选题自动创作整个视频。

**实际开始使用时，我建议这样选。**

科幻作业先在 **LTX Studio 或 Toonflow 中二选一**：把物理设定和剧本确定下来，生成角色、场景与短样片，检查连续性后再扩展成片。若要额外拼入实拍，把导出片段交给支持原片剪辑的编辑器。ViMax 留给你决定长期建立程序化制作流程时使用。

科学讲解先准备好真实实验或自然现象片段与对应讲稿，用 **Fliki 直接编排配音、字幕和画面**；若倾向开源并希望继续精修时间线，则用 **NarratoAI 导出剪映草稿**。只在确实需要解释看不见的量、变化关系或数学结构时，加入一段 Manim 动画。MoneyPrinterTurbo 更适合在你已有规范素材和固定制作方式后扩大产量。

对这两个需求，最值得保留的人工工作是物理设定、实拍片段选择、关键镜头检查；剧本拆分、候选画面、配音、字幕和合成可以交给这些项目。这样既能获得较高的自动化程度，也能把精力放在课程作品最需要准确表达的内容上。
